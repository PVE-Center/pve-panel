# Security Policy

## Supported Versions

Security fixes are applied to the active `main` branch of `PVE-Center/pve-panel`:

| Version / Branch | Supported |
|---|---|
| `main` (v1.0.x) | Yes |
| Older commits | No |

## Reporting a Vulnerability

**Please do NOT open a public GitHub Issue for security vulnerabilities.**

Instead, report vulnerabilities privately through GitHub Security Advisories:

- **[Report a security vulnerability](https://github.com/PVE-Center/pve-panel/security/advisories/new)**

When submitting a report, please include:

- A clear description of the vulnerability and its potential impact
- Affected component(s) (e.g., DualAuth middleware, `/api/pairing/*`, `ConfigManager`, `install.sh`)
- Steps to reproduce or a minimal proof-of-concept
- Any suggested remediation if known

We aim to acknowledge reports within **48 hours** and coordinate remediation before public disclosure.

## Built-in Security Safeguards

`pve-panel` implements defense-in-depth protections for homelab environments:

- **DualAuth ASGI Middleware** (`backend/app/middleware/tailscale_auth.py`):
  - Loopback requests (`127.0.0.1` / `::1`) require valid `Tailscale-User-Login` headers matching `security.allowed_tailscale_users`, a valid `Authorization: Bearer` token, or explicit `dev_auth_bypass: true`.
  - Non-loopback LAN, WebSocket, and SSE clients require `Authorization: Bearer <token>` (or `?token=` for WS/SSE) verified in constant time (`hmac.compare_digest`) against SHA-256 hashes in `security.api_tokens` or HS256 JWTs signed with `security.session_secret`.
  - Initial onboarding (`POST /api/onboarding/init`) is automatically locked down (`401`/`403`) once `is_configured()` becomes `true`.
- **Credential Hygiene**:
  - Admin PINs are hashed with `PBKDF2-HMAC-SHA256` (200,000 iterations, random 16-byte salt).
  - Secret fields returned over HTTP (`/api/config/yaml`, `/api/setup/status`, `/api/notifications/channels`, `/api/custom-services`) are masked with `********` or boolean `*_set` flags, while `${VAR_NAME}` environment placeholders are preserved on save.
  - Files generated by `install.sh` (`config/config.yaml`, `.env`) are written with `0600` permissions inside a `0700` `config/` directory.
- **Rate Limiting & Pairing Security**:
  - `POST /api/auth/login` limits failed attempts per client IP (`10` failures per `60s` window).
  - Apple TV pairing relay sessions (`/api/pairing/sessions`) expire after `300s`, enforce `10` lookups per `60s` rate limiting, clear payloads after single retrieval, and only relay client-side `P-256 ECDH` + `HKDF-SHA256` + `AES-256-GCM` ciphertext.
- **Proxmox Self-Shutdown Guard**:
  - `proxmox.panel_self_vmid` prevents stopping or shutting down the LXC/VM hosting `pve-panel` itself.

## Operator Best Practices

1. Never enable `DEV_AUTH_BYPASS=true` (`dev_auth_bypass: true`) in production.
2. Always use `${VAR_NAME}` environment references or masked UI inputs rather than committing secrets; keep `.env`, `config/config.yaml`, `services.yaml`, `*.db`, and `AuthKey.p8` out of version control.
3. Grant the Proxmox API token (`root@pam!pve-panel`) only the minimal `PanelRole` privileges (`Sys.Audit VM.Audit Datastore.Audit VM.PowerMgmt`).
